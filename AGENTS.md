# TULBOXX Website Blueprint
## AI & Contributor Operating Manual

**Version:** 1.0
**Status:** Canonical
**Applies To:** Every AI agent, developer, designer, copywriter, marketer, and contributor working on the TULBOXX marketing website.

---

# Purpose

This repository is the strategic source of truth for the TULBOXX marketing website.

It exists to define **why** the website exists before defining **how** it should be built.

The production website (`tulboxx-web`) should always implement the decisions documented here. When implementation and documentation conflict, update the implementation—not the strategy—unless the strategy has been intentionally revised.

---

# Repository Mission

The purpose of this repository is to ensure every page, image, animation, component, and line of copy tells one consistent story.

This repository is not documentation for software.

It is documentation for belief.

Visitors should leave believing:

- Running a service business doesn't have to feel chaotic.
- There is a better way.
- TULBOXX understands contractors.
- TULBOXX can help them become more organized, professional, and profitable.

---

# Source of Truth Hierarchy

All work should follow this order.

```
Product Vision
        ↓

        ↓

        ↓

        ↓

        ↓
```

Never skip levels.

Never TULBOXX.

# What We Sell

We do not sell software.

We sell transformation.

We help contractors become:

- More organized
- More professional
- More confident
- More profitable

---

# Product Philosophy

The website should reinforce the Product Vision.

Key principles include:

- Contractors already know how to do the work.
- Software should adapt to contractors—not the other way around.
- Simple jobs stay simple.
- Complex jobs remain possible.
- Enter information once.
- AI organizes.
- Contractors decide.

Never contradict the Product Vision.

---

# Messaging Principles

Always communicate outcomes before features.

Instead of:

"AI Estimates"

Prefer:

"Win More Jobs."

Instead of:

"CRM"

Prefer:

"Never Lose Track of a Customer Again."

Instead of:

"Scheduling"

Prefer:

"Know What's Happening Every Day."

People buy better businesses.

Not software.

---

# Voice

Write like an experienced contractor talking to another contractor.

Be:

- Clear
- Direct
- Honest
- Practical
- Helpful
- Confident

Never be:

- Corporate
- Buzzword-heavy
- Overly technical
- Clever for the sake of cleverness
- Condescending

How It Works

Features

---

# Design Philosophy

Design should communicate confidence.

Not decoration.

Every image exists to explain something.

Every animation exists to improve understanding.

Every screenshot exists to support copy.

No decorative dashboards.

No meaningless illustrations.

No unnecessary animations.

---

# Photography

Prioritize:

- Real contractors
- Dirty boots
- Trucks
- Equipment
- Job sites
- Tablets and phones in the field
- Customers
- Finished work

Avoid:

- Stock office workers
- Fake handshakes
- People pointing at monitors
- Generic SaaS imagery

---

# Dashboard Philosophy

The product should feel:

Simple.

Fast.

Professional.

Never crowded.

Never intimidating.

Users should feel capable within seconds.

---

# AI Philosophy

AI is not the headline.

AI is quiet leverage.

It should feel like:

"I got this done faster."

Not:

"Look what AI can do."

---

# Copy Philosophy

Every section should answer one question.

Every paragraph should earn the next paragraph.

Every headline should create curiosity.

Every CTA should reduce friction.

Never write filler.

---

# SEO Philosophy

Write for humans first.

Optimize second.

Every page should solve a real problem.

Every page should have a clear search intent.

Never sacrifice readability for keywords.

---

# Components

Components should reinforce understanding.

Cards explain.

Animations demonstrate.

Timelines clarify.

Icons support.

Nothing exists only because it looks nice.

---

# Development Philosophy

The marketing website should feel:

Fast.

Premium.

Intentional.

Modern.

Accessible.

Responsive.

Performance is part of the brand.

---

# Decision Filter

Before making any change, ask:

1. Does this help contractors?
2. Does it reduce confusion?
3. Does it increase trust?
4. Does it reinforce the Product Vision?
5. Would we still build this if no competitor had it?
6. Is there a simpler solution?

If not, reconsider.
