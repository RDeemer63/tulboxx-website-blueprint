# VISUAL_STORYBOARD.md

# TULBOXX Visual Storyboard

**Version:** 1.0
**Status:** Canonical
**Purpose:** Define what every major visual on the TULBOXX marketing website should communicate, how it should make the visitor feel, and which visual format best supports the story.

---

# Core Rule

Every visual must do at least one of these things:

* Explain how TULBOXX works.
* Help the contractor recognize their own reality.
* Build trust.
* Demonstrate transformation.
* Reduce uncertainty.
* Reinforce the brand.

If a visual does none of those things, it should not exist.

---

# Visual Philosophy

TULBOXX should not look like generic SaaS.

It should feel:

* Real
* Premium
* Industrial
* Modern
* Field-first
* Confident
* Simple
* Useful

The website should combine:

* Real contractors
* Real jobsite environments
* Real product UI
* Clear workflow visuals
* Minimal but meaningful motion

The product should never float in an abstract tech universe.

It should always feel connected to real work.

---

# Visual Hierarchy

Use this order of preference:

1. Real contractor photography
2. Real TULBOXX product UI
3. Product + field environment compositions
4. Workflow diagrams
5. Motion demonstrations
6. Simple icons
7. Illustrations only when photography or UI cannot explain the idea

Avoid decorative visuals.

# Homepage Visual Story

## Section 1 — Hero

### Emotional Goal

Relief.

Possibility.

Control.

The visitor should immediately feel:

"This looks like software built for someone like me."

### Recommended Visual

A real contractor sitting in or beside a truck at a jobsite.

Phone or tablet visible.

Equipment or finished work in the background.

TULBOXX UI subtly integrated into the scene.

The contractor should not look staged.

They should look like they are finishing real work.

### Product UI Overlay

Use only 2–3 UI elements.

Examples:

* Estimate sent
* Job scheduled
* Invoice paid

These should visually support the idea that the business is moving forward.

Do not cover the image with ten floating cards.

### Motion

Subtle.

UI cards can appear one at a time.

No aggressive parallax.

No spinning dashboards.

# Product Screenshots

Screenshots should always be curated.

Never dump entire screens without a reason.

Crop to the relevant interaction.

Use callouts sparingly.

The visitor should understand the point within three seconds.

---

# Mobile Product Visuals

Mobile should appear frequently.

TULBOXX is field-first.

A website showing only desktop screens sends the wrong message.

Recommended ratio:

Approximately 50% mobile.

Approximately 50% desktop/tablet.

Depending on workflow.

# Motion System

Use motion to communicate:

Progress.

Connection.

Transformation.

Completion.

Avoid motion that exists only to look impressive.

Preferred motion:

* Fade
* Slide
* Progressive reveal
* Connected workflow
* Status transitions
* Before / after
* UI state changes

Avoid:

* Excessive parallax
* Constant floating
* Random rotation
* 3D effects without purpose
* Scroll hijacking

# Photography Direction

`PHOTOGRAPHY_DIRECTION.md` is the canonical photography standard. It governs camera language, lighting, color, composition, contractor continuity, image-generation prompts, and post-processing. The rules below are a summary and must not be used to override it.

Photography should feel:

Natural.

Warm.

Grounded.

Documentary.

Professional.

Avoid images that feel overly commercial.

Lighting should generally feel real.

Outdoor natural light is preferred.

Jobsite environments should not be excessively cleaned or staged.

---

# Image Generation Guidance

Use the master prompt requirements and prohibited-content rules in `PHOTOGRAPHY_DIRECTION.md` for every generated photograph.

When AI-generated photography is necessary, prompts should prioritize:

* Realistic tradespeople
* Authentic jobsite environments
* Natural body positions
* Practical clothing
* Real tools
* Real equipment
* Dirt and imperfection
* Natural lighting
* Documentary photography

Avoid:

* Perfect teeth
* Fashion poses
* Unrealistically clean clothing
* Cinematic superhero lighting
* Exaggerated muscles
* Generic construction stock-photo poses

# Typography

Headlines:

Rajdhani Bold

Body:

Poppins

Headlines should feel strong and industrial.

Body text should remain highly readable.

Large typography is encouraged.

Especially for outcome-based statements.

---

# Visual Density

The site should breathe.

Do not cram every section.

Use large spacing between ideas.

Give strong headlines room.

Use fewer elements at larger scale.

Premium design comes from restraint.

---

# Final Visual Test

Before approving any image, animation, screenshot, or illustration, ask:

1. What does this explain?
2. What should the visitor feel?
3. Does this look like the contractor's real world?
4. Does this make TULBOXX easier to understand?
5. Could this visual belong to any generic SaaS company?

If the answer to #5 is yes, improve it.

---

# Final Principle

The website should not look like software sitting on top of the trades.

It should look like software that belongs inside the trades.

Every visual should reinforce that truth.
